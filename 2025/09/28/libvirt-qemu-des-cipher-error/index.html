libvirt QEMU DES加密算法不支持错误解决方案

echoker 2025-09-28 19:01:31
Categories： 虚拟化 Tags： libvirt QEMU VNC

问题描述

在使用libvirt启动QEMU虚拟机时，遇到了以下错误：

libvirt: QEMU Driver error : internal error: qemu unexpectedly closed the monitor: 2025-09-28T19:01:31.026930Z qemu-system-x86_64: -vnc 0.0.0.0:4101,password=on,audiodev=audio1: Cipher backend does not support DES algorithm

这个错误表明QEMU在启动时因为VNC配置中的DES加密算法不被当前系统的加密后端支持而失败。

错误原因分析

该错误的根本原因是：

  • DES算法过时：DES (Data Encryption Standard) 是一种较老的加密算法，由于安全性较低，现代系统逐渐停止支持
  • 系统加密库更新：新版本的OpenSSL或其他加密库可能已经移除了对DES的支持
  • VNC配置问题：libvirt配置中VNC连接使用了DES加密，但系统不支持

解决方案

方案一：修改VNC配置移除密码认证

最直接的解决方案是修改虚拟机的XML配置，移除VNC的密码认证：

<!-- 原配置 -->
<graphics type='vnc' port='-1' autoport='yes' passwd='your_password'/>

<!-- 修改后的配置 -->
<graphics type='vnc' port='-1' autoport='yes'/>

使用virsh命令修改：

# 编辑虚拟机配置
virsh edit your_vm_name

# 或者使用命令行直接修改
virsh dumpxml your_vm_name > vm_config.xml
# 编辑xml文件移除passwd属性
virsh define vm_config.xml

方案二：使用更安全的认证方式

配置SASL认证替代传统的VNC密码：

<graphics type='vnc' port='-1' autoport='yes'>
  <listen type='address' address='0.0.0.0'/>
</graphics>

然后在/etc/libvirt/qemu.conf中配置SASL：

# 启用SASL认证
vnc_sasl = 1
vnc_sasl_dir = "/etc/sasl2"

方案三：使用SPICE替代VNC

SPICE协议提供更好的性能和安全性：

<graphics type='spice' port='-1' autoport='yes'>
  <listen type='address' address='0.0.0.0'/>
  <image compression='off'/>
</graphics>

方案四：系统级修复（仅适用于兼容性需求）

如果必须使用DES，可以考虑以下选项（不推荐，仅用于旧系统兼容）：

# Ubuntu/Debian系统
sudo apt-get install libssl1.1

# CentOS/RHEL系统
# 可能需要编译支持DES的OpenSSL版本

# 检查当前OpenSSL支持的加密算法
openssl list -cipher-algorithms | grep -i des

预防措施

  • 定期更新配置：随着系统更新，及时检查并更新虚拟机配置
  • 使用现代认证：避免使用过时的加密算法，采用更安全的认证方式
  • 测试环境验证：在生产环境部署前，先在测试环境验证配置
  • 监控日志：定期检查libvirt和QEMU日志，及早发现潜在问题

命令行操作示例

# 查看虚拟机列表
virsh list --all

# 查看虚拟机当前配置
virsh dumpxml vm_name

# 编辑虚拟机配置
virsh edit vm_name

# 重启libvirt服务（修改配置后）
sudo systemctl restart libvirtd

# 启动虚拟机
virsh start vm_name

# 查看虚拟机VNC端口
virsh vncdisplay vm_name

验证解决方案

修改配置后，可以通过以下方式验证：

# 检查虚拟机是否正常启动
virsh list

# 查看libvirt日志
sudo journalctl -u libvirtd -f

# 测试VNC连接
vncviewer localhost:display_number

总结

DES加密算法不支持的错误主要是由于系统安全性升级导致的。推荐的解决方案是移除VNC密码认证或使用更安全的认证方式，而不是降级系统加密库。这样既能解决当前问题，又能保持系统的安全性。

对于生产环境，建议采用SPICE协议或配置适当的网络安全措施（如VPN、防火墙规则）来保护虚拟机的远程访问。
